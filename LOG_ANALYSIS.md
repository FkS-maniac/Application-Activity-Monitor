# Анализ присланного диагностического отчёта Beta 0.4

Источник: локальный TXT, сформированный 2026-10-31. В этот пакет исходный TXT не включён.

Факты:
- Windows 11, Python 3.13.12; WMI x_access_denied при подписке, source=polling.
- Uptime 127.4 s; 161 неудачная детекция, 158 сообщений о повторах подавлены.
- 169 success-событий, 169 уникальных instance: этот фрагмент не доказывает дубли одного запуска.
- Из 169 успешных процессов 108 в Other, 51 Browser, 6 Communication, 3 System, 1 Games. Это процессы, не уникальные приложения.
- В live snapshot 299 observed, 2 inflight, 63 приложения, pending 304, spool 0. pending не равен количеству активных задач.
- В первом metrics.snapshot spool=502, позже=0: очередь на этом фрагменте разгружалась. Доказательств бесконечного роста нет.
- Ошибки явно включают PID 0, PID 4, доступ к winlogon.exe. В принятых процессах есть RuntimeBroker, svchost, TextInputHost и другие OS-задачи текущей пользовательской сессии.
- 11 приблизительных закрытий при polling. Это ожидаемое ограничение источника, не доказательство аварий процессов.
- JSON traceback содержал домашний Windows-путь несмотря на маскировку отчёта.

Изменения:
- Дешёвые фильтры PID/имени/SessionID до username/exe.
- Настраиваемый список OS-background имён, allowlist override только этой эвристики.
- Снимок не отправляет неизменившиеся процессы повторно: batched last_seen.
- Пакетный вход spool, сигнал пробуждения после выполнения детекции.
- Разделены parked и pending в метриках, source_reason виден пользователю.
- Ожидаемый AccessDenied без полного traceback каждый раз; ограничения частоты и счётчики сохранены.
- Маскировка plain и JSON escaped путей покрыта отдельными тестами.
- Расширены категории для имён из отчёта без копирования персональных путей.
- Mutex предотвращает второй экземпляр RC.

Нет измерений CPU/RAM новой версии на Windows. average_ms в старом отчёте измеряет время задания, не нагрузку CPU. Не обещается исправление прав WMI автоматически, постоянная нагрузка или полная точность закрытий при polling.
